# Domain documentation

Ratatoskr uses a single-context domain-document layout.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read relevant architectural decision records under `docs/adr/` when they exist.
- If either location is absent, proceed without inventing placeholder domain documentation. Create domain records only when terminology or an architectural decision is actually settled.

## Vocabulary

Use domain terms as defined in `CONTEXT.md`. Do not replace defined terms with near-synonyms in issue titles, plans, tests, or implementation notes. If a required concept is not defined, first determine whether it is existing repository language or a genuine modeling gap.

## Architectural decisions

Surface conflicts with an existing ADR explicitly. Do not silently override an accepted decision in implementation or planning work.
